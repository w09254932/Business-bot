# Telegram Business Monitor

بوت Telegram Business مبني باستخدام Python وFastAPI.

## الوظائف الحالية
- استقبال تحديثات Telegram Business.
- إشعارات الرسائل الجديدة والمعدّلة والمحذوفة.
- إعادة إرسال الوسائط المتاحة باستخدام Telegram file_id.
- وحدة مستقلة لمحاولة استعادة الوسائط الموجودة في الرسائل المردود عليها.
- دعم الصور والفيديو والصوت والملفات والملصقات.
- منع معالجة التحديث نفسه مرتين.
- تنظيف النسخ المؤقتة وفق مدة الاحتفاظ والحد الأقصى.
- حماية Webhook باستخدام Telegram secret token.

## التخزين الحالي
## التخزين
- عند ضبط FIREBASE_SERVICE_ACCOUNT_JSON تُحفظ اتصالات Telegram Business في Firestore.
- مسار الاتصالات: users/{owner_id}/business_connections/{connection_id}.
- تُستعاد الاتصالات المحفوظة عند بدء التطبيق.
- عند عدم ضبط متغير Firebase يعمل التطبيق في وضع RAM فقط.
- نسخ الرسائل المؤقتة ومعرفات التحديثات تبقى في RAM وتُفقد عند إعادة التشغيل.
- لا تُحفظ نصوص المحادثات أو الوسائط في Firestore في هذه المرحلة.
- لا يتم تنزيل ملفات الوسائط أو رفعها إلى طرف ثالث.

## التشغيل المحلي
1. انسخ `.env.example` إلى `.env`.
2. أدخل BOT_TOKEN وWEBHOOK_SECRET.
3. ثبّت المتطلبات:

   `python -m pip install -r requirements.txt`

4. شغّل التطبيق:

   `uvicorn app.main:app --reload`

5. شغّل الاختبارات:

   `python -m pytest -q`

## النشر على Render
- أمر التشغيل:
  `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
- يتطلب BOT_TOKEN وWEBHOOK_SECRET في متغيرات البيئة.
- يستخدم التطبيق RENDER_EXTERNAL_URL لتسجيل Webhook عند التشغيل.
- مسار فحص الصحة: `/health`.

## قيود مهمة
- إعادة تشغيل الخدمة تفقد اتصالات Business والنسخ المؤقتة.
- استعادة الوسائط المؤقتة ليست مضمونة؛ تعتمد على البيانات التي يتيحها Telegram للبوت.
- تحديثات حذف الرسائل لا تتضمن محتوى الرسالة المحذوفة؛ يعتمد الإشعار والاسترجاع على النسخة المؤقتة المتاحة.
- لا تستخدم النسخة الحالية كأرشيف دائم للبيانات.
